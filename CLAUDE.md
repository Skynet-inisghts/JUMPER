# CLAUDE.md: rules for the JUMPER repo

Full spec in `JUMPER_SPEC.md`. This file holds the rules every session follows.

## Hard rules
- Read only. No `PRIVATE_KEY`, `privateKeyToAccount`, `signTransaction`, `sendTransaction`, `writeContract`, `walletClient`, `signMessage` anywhere in `src/`, `web/`, `bin/`. The CI job `no-signer` greps for them.
- Never read `tx.from`: on this chain it is the relayer. The trader always comes from the event's own fields. A test greps for it.
- Routers: trades and balances are credited to the wallet at the far end of a same-block pass-through (`src/crawlers/weaver.ts`).
- The site never asks to connect a wallet, carries no roadmap, no trackers, no predictions. The score describes the past.
- Do not rename the crawlers or the scale (TORN / PATCHED / TAUT, labels TORN LOOSE PATCHED HOLDING TAUT SILK): they are in the brand and in posts.
- Never hardcode the index URL or any key. Keys live in `.env` and in the host's environment.

## Code
- Engine in `src/` (TypeScript, NodeNext ESM, explicit `.js` specifiers). Crawlers are pure functions over a Tape; network reads only in `src/chain/` and `src/crawl.ts`.
- Weights and thresholds only in `src/score/config.ts`. A change that moves the fixture numbers in `test/fixtures.test.mjs` says why in its commit.
- The site in `web/` builds with webpack (`next build --webpack`), Turbopack cannot resolve the engine's `.js` specifiers.
- Brand assets are generated by `assets/brand/mascot.py`; change the generator, not the PNGs.
- Code, README, docs, comments, commits, CLI and site text: English. Commits short, lowercase: `weaver: credit routed sales to the sender`.

## Before a commit
`pnpm check` is green (typecheck, tests, site typecheck, lint, build).

## Releases
Every milestone is a version in `CHANGELOG.md` with a date, a git tag, and the README updated in the same change.
